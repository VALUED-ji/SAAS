# 客户详情 UI 组件与设计规范

日期：2026-07-27

## 产品定位

- 页面类型：装修行业客户生命周期工作台。
- 核心用户：家装顾问、设计师、项目经理、管理人员。
- 核心任务：识别客户当前状态、推进下一步业务、查看资料与款项、完成审批和团队协作。
- 视觉语言：Soft Enterprise + Neutral Chrome，强调清晰、克制和稳定的日常操作效率。

## 保护边界

- 不修改 API、数据结构、权限、数据范围、排序和默认值。
- 不修改客户状态流、审批流、款项、报价、合同或附件业务逻辑。
- 只调整 UI 结构、组件复用、视觉层级、滚动和交互状态。
- 路由作用域仅覆盖 `/projects/[id]`，不影响 `/projects` 客户列表和工地详情。

## 尺寸体系

- 主面板圆角：`16px`。
- 弹窗圆角：`18px`。
- 输入框、按钮、图标按钮：`10px`。
- 内部信息组：`12-14px`。
- 状态标签：胶囊形。
- 普通控件高度：`40px`，触控区域不得小于 `40px`。
- 页面模块间距：`16-20px`。
- 面板内边距：`20px`，移动端 `16px`。

## 标准组件

源码：`src/components/projects/customer-detail-ui.tsx`

- `CustomerDetailPanel`：详情页主面板。
- `CustomerDetailSectionHeader`：图标、标题、描述和操作入口。
- `CustomerDetailEmptyState`：资料、记录和列表空状态。
- `CustomerDetailDialog`：带遮罩、固定头部、可滚动内容和固定底部操作的业务弹窗。
- `DetailInfoField`：客户字段信息项，通过稳定语义类名组成连续信息网格。

## 页面结构

1. 客户档案头：头像、客户名、状态、来源、联系方式和关键操作。
2. 下划线 Tab：保留原有 Tab、顺序和切换逻辑。
3. 生命周期：明确当前阶段，弱化未到达阶段，说明当前推进动作。
4. 客户信息：三列连续描述网格，避免每个字段形成独立厚重卡片。
5. 服务团队：核心岗位与其他参与人员统一为紧凑人员行。
6. 业务 Tab：量房、设计、款项、报价、合同和操作记录统一面板、表头、表格和空状态。

## 弹窗层级

### 一级业务弹窗

- 用于编辑客户、收定金、退款、合同创建和审批详情。
- 宽度按业务内容设置，头部与底部固定，正文独立滚动。
- 标题说明业务对象，主操作位于右下角。

### 二级选择弹窗

- 用于人员、设计师、模板和组织选择。
- 保留搜索、筛选、结果数量、空状态和选中态。
- 选项使用紧凑资源行，不使用大面积蓝色背景。

### 附件预览弹窗

- 使用更宽画布，头部保留文件名、类型、时间和打开/下载操作。
- 图片、PDF、在线链接和不支持预览状态保持原有功能。
- 预览画布使用中性灰背景，不使用大面积浅蓝铺底。

## 状态与可访问性

- 键盘焦点使用 `#407AFF` 半透明焦点环。
- 主操作、危险操作和成功操作使用不同语义色，不能只依赖颜色表达含义。
- 弹窗包含 `role="dialog"`、`aria-modal`、可访问名称和明确关闭入口。
- loading、错误、空状态保留原业务文案，并使用稳定尺寸避免布局跳动。
- 动画遵循 `prefers-reduced-motion`，不阻塞输入和操作。
