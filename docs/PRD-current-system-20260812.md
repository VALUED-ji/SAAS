# 装企端星艺 SaaS 系统 PRD 产品需求文档

版本：v2.0  
日期：2026-08-12  
适用范围：当前完整 PC 端 SaaS 系统  
文档目标：用于产品梳理、研发交接、测试验收、UI 统一升级、后续功能规划  

## 1. 产品概述

装企端星艺 SaaS 是面向装修公司内部经营管理的一体化业务系统，覆盖客户获客、跟进、量房、设计方案、报价、合同、收款、退款、施工、工地签到、施工记录、摄像头、资料归档、材料、供应商、辅材订单、组织权限、分公司规则配置、合同模板配置和经营数据分析。

系统定位不是营销官网，也不是轻量 CRM，而是装修公司日常经营使用的核心业务后台。系统需要支持老板、管理层、门店负责人、设计师、项目经理、财务、材料/订单人员和系统管理员在同一套平台内协作，并确保权限、财务、安全和操作留痕可追溯。

## 2. 产品目标

### 2.1 业务目标

- 统一装修公司从客户到工地交付的全流程管理。
- 帮助管理层实时掌握客户新增、签约、收款、工地进度、成本和团队待办。
- 帮助一线员工减少重复录入，提高跟进、报价、签约、收款、施工记录效率。
- 建立可配置的分公司业务规则，包括审批流、收款比例、施工模板、合同模板、打印设置、材料下单设置等。
- 让财务数据、审批数据、合同数据、资料附件具备可追溯性和权限边界。
- 支持正式环境安全部署、可备份、可回滚，避免开发更新影响正式用户数据。

### 2.2 用户体验目标

- 整体遵守现代 SaaS Dashboard 风格，信息层级清晰、留白合理、操作路径明确。
- 列表页适合高频筛选和快速定位；详情页适合围绕一个客户或工地连续操作。
- 报价、合同、收款、审批等高频流程要减少用户疑惑，关键状态必须明显。
- 表单、弹窗、Tab、下拉、分页、表格统一使用新 Design System，不再出现多套 UI 混杂。
- 错误、过期登录、权限不足等情况应给出明确提示，不要求用户刷新后才发现问题。

## 3. 产品边界

### 3.1 当前包含

- PC 端业务后台。
- 多租户公司数据隔离。
- 登录与会话管理。
- 组织、员工、角色、权限与数据范围。
- 客户管理与客户详情。
- 跟进记录、跟进回复、附件、提及。
- 量房资料和设计方案归档，含扫码上传。
- 定金、设计费、退款、审批与签名。
- 报价合同、报价编辑、模板带入、报价导出和分享。
- 合同资料、合同模板、Word 导入、合同打印。
- 工地列表与工地详情。
- 开工交底、施工模板、施工计划、施工阶段、施工记录。
- 工地签到、工地摄像头、资料归档、成本支出、增减项。
- 财务中心，包括业主收款和人工结算。
- 定额库、定额模板。
- 辅材订单、材料库、库存、入库单、供应商。
- 集团总览、经营总览、待办中心。

### 3.2 当前不包含或暂不作为主目标

- 面向业主的完整移动端 App。
- 面向获客的官网/营销页。
- 银行支付通道自动对账的完整闭环。
- 第三方电子签章平台深度集成。
- 多数据库/微服务架构改造。
- 跨公司集团主数据治理平台。

## 4. 用户角色与权限

| 角色 | 核心职责 | 高频模块 | 权限重点 |
|---|---|---|---|
| 老板/集团管理层 | 看集团经营、分公司经营、财务结果、团队效率 | 集团总览、经营总览、待办中心、财务中心、组织权限 | 可查看集团/大区/公司范围数据，管理关键配置 |
| 门店/分公司负责人 | 管理门店客户、报价、签约、施工和员工 | 经营总览、客户管理、报价合同、工地管理、团队管理 | 管理本公司/门店及下级数据 |
| 设计师 | 客户跟进、量房、设计方案、报价、合同发起 | 客户详情、报价合同、合同资料、待办中心 | 查看和操作自己服务客户 |
| 项目经理 | 开工交底、施工计划、节点完成、工地记录、材料下单 | 工地管理、施工记录、材料下单、资料归档 | 管理自己负责工地 |
| 财务 | 收款、退款、审批、业主款项、人工结算 | 财务中心、待办中心、客户/工地款项 | 财务查看、收款审核、退款处理 |
| 材料/订单人员 | 材料维护、库存、供应商、辅材订单 | 材料管理、订单管理、供应商管理 | 材料与订单管理 |
| 系统管理员 | 组织、角色、基础资料、系统配置 | 组织权限、分公司设置、系统设置 | 系统配置与权限维护 |

权限原则：

- 前端按钮隐藏只作为体验优化，所有接口必须服务端校验登录、权限和数据范围。
- 敏感字段，如手机号、地址、财务金额、合同内容、摄像头验证码，应按权限显示或脱敏。
- 财务记录、审批记录、合同记录、操作日志默认不可物理删除，除草稿、临时数据外应保留历史。
- 账号过期或会话失效时，用户点击任意功能应自动跳回登录页并提示“登录已过期，请重新登录”。

## 6. 全局体验规范

### 6.1 应用框架

- 左侧菜单展示系统模块，支持一级菜单展开/收起，二级菜单无多余符号。
- 菜单间距、图标尺寸、文字层级统一；待办中心数量显示在菜单右侧，红色圆形角标。
- 左上角品牌区支持按登录账号组织动态显示：
  - 集团账号显示集团名称。
  - 大区账号显示大区名称。
  - 公司账号显示公司简称。
  - 公司以下组织账号显示公司简称。
  - 公司简称未配置时默认显示“星艺装饰”。
  - 英文统一显示为 `XINGYI DECORATION`，如分公司未配置英文副标题则隐藏并保持 logo 与名称上下居中。
- 分公司可配置品牌 Logo、公司简称和品牌副标题；集团/大区未配置时使用系统默认 Logo。

### 6.2 Design System

- 主色：新蓝色 `#407AFF`，只用于主按钮、激活态、焦点态、关键文字，不做大面积铺底。
- 页面背景：`#F6F7F9`。
- 主面板：白色。
- 次级区域：`#FAFAF9` 或极浅灰。
- 边框：低对比中性灰，如 `#E7E9EE`。
- 内容面板默认圆角 `16px`，弹窗默认圆角 `18px`，输入框/下拉/普通按钮默认圆角 `10px`，状态标签保留胶囊。
- 表格金额列右对齐，状态列居中，文本列左对齐。
- 页面级阴影应克制；顶部、列表、详情面板不使用厚重阴影。
- 弹窗、下拉、表格、分页、筛选区、Tab 要全系统统一，不允许同类组件多套样式并存。

### 6.3 交互原则

- 列表支持搜索、筛选、分页；搜索应防抖。
- 大表格应支持横向滚动且固定关键操作区。
- 表单保存失败保留用户已填内容。
- 金额输入避免无效前导 0，展示保留两位小数，财务中心不显示 `¥` 和千分位。
- 高风险操作必须二次确认，包括删除、停用、退款、冲销、审批驳回、发布替换模板。
- 页面加载使用简洁转圈/轻量空状态，不使用堆叠复杂骨架屏。

## 7. 核心业务流程

### 7.1 客户到签约流程

1. 新增客户：录入姓名、手机号/微信、小区楼盘、地址定位、房号、面积、预算、来源、服务门店、邀约人等。
2. 分配团队：设置邀约人、设计师、项目经理等服务团队角色。
3. 跟进客户：记录电话、微信、量房、报价、签约等跟进内容，可上传附件，可 @ 提及团队成员。
4. 量房资料：通过客户详情或扫码上传量房资料，按资料类型归档。
5. 设计方案：上传平面图、效果图、在线链接等设计方案资料。
6. 收定金/设计费：记录定金或设计费，可配置固定金额、按报价合计、按直接费、按设计师等级面积计算。
7. 创建报价：选择客户和定额模板，系统自动带入空间、项目、综合费用。
8. 报价确认：报价可编辑、复制、导出、分享、发送给设计师确认，最终设为正式报价。
9. 创建合同：选择合同类型、合同模板和正式报价，生成合同金额、收款计划和合同正文。
10. 合同审批/签约：按分公司审批流程审批，审批需要签字；签约后进入待开工/工地管理。

### 7.2 工地施工流程

1. 签约客户进入工地列表。
2. 项目经理完成开工交底，必须选择施工模板并填写计划开工、签约工期等关键字段。
3. 确认开工时校验交底已完成且施工模板有效。
4. 系统根据施工模板生成施工阶段、施工节点和计划周期。
5. 项目经理在施工阶段中推进节点状态：待完成、进行中、待确认/待验收、已完成/已验收。
6. 施工节点状态、附件、汇报、问题整改会进入施工记录，方便用户快速查看节点相关操作。
7. 可记录工地签到、日报、照片、资料归档、成本支出、材料下单、增减项。
8. 工地摄像头可接入萤石，进入摄像头 Tab 后自动尝试播放实时画面。
9. 工地完工后进入业主结算、工地结算等后续状态。

### 7.3 财务收款与退款流程

1. 财务中心按工地查看业主收款。
2. 款项类型包括定金、设计费、工程款、变更款。
3. 款项列表默认最近记录在最上方。
4. 主动收款时必须明确选择定金或设计费，降低误操作。
5. 收款可进入审批流程，审批节点需要签字。
6. 退款包括退定金、退设计费、退工程款、退变更款；驳回状态前端显示为“已关闭”。
7. 退款状态包括审核中、待打款、打款中、退款完成、已关闭。
8. 财务流水必须保留，错误处理通过冲销或状态变更追踪，不直接删除正式流水。

### 7.4 报价流程

1. 管理员维护定额库和定额模板。
2. 报价员新建报价时选择客户和模板。
3. 模板支持空间、项目、套餐计价、综合费用、报价分类。
4. 报价详情页支持类似 Excel 的键盘方向键移动输入框。
5. 报价可调整空间、分类、项目、数量、人工费、材料费、综合费用、折扣、税费等。
6. 综合费用可按固定金额、比例、引用基数计算，避免人工重复计算。
7. 报价支持保存、复制副本、删除/恢复、设为正式报价、发送设计师、导出表格、打印/分享。

### 7.5 合同模板与合同打印流程

1. 分公司设置中维护合同模板。
2. 支持多套模板，按合同类型区分。
3. 同一个合同类型只能有一个已发布可用模板；发布新模板时自动停用同类型旧模板，并二次确认。
4. 模板状态包括草稿、已发布、已停用。
5. 草稿模板支持删除；已发布或曾发布过的模板不能删除，只能停用。
6. 保存和发布分开，保存仅保存草稿/版本，发布后才可用于客户合同。
7. 支持导入 `.docx` Word 文件，尽量保留原 Word 样式，导入后可继续编辑。
8. 编辑器支持分页预览、页面间距、字体、字号、段落、文字颜色、高亮、加粗、斜体、下划线、动态变量和动态块插入。
9. 合同创建时可选择模板；提交审批或创建合同时冻结模板版本，历史合同不受后续模板修改影响。
10. 客户合同资料中可快速打印合同。

## 8. 模块需求明细

### 8.1 登录

目标：员工安全登录系统并建立有效会话。

功能要求：

- 手机号/账号与密码登录。
- 登录失败提示“账号或密码错误”等清晰信息。
- 登录尝试过多进行限流。
- 密码正确后写入会话 Cookie，更新最后登录时间和在线时间。
- 会话过期后自动退出到登录页。
- 登录页主色可与后台主色区分，允许保留原品牌蓝。

验收标准：

- 错误密码返回明确提示，不出现白屏。
- 正确密码可进入默认工作台。
- 缺失服务端密钥、账号公司不可用等异常不能暴露内部堆栈。

### 8.2 集团总览

目标：给集团/大区管理者提供跨组织经营视角。

功能要求：

- 支持按时间范围查看集团经营指标。
- 支持今天、昨天、最近 7 天、最近 30 天、本月、上月、本季度、本年、自定义时间。
- 支持省份/大区维度切换。
- 展示新增客户、签约金额、签约数、收款、转化等核心指标。
- 展示组织排行、趋势图、分公司经营表格。
- 大屏自适应，内容随宽度扩展，不挤在左侧。

### 8.3 经营总览

目标：给分公司/门店管理者提供日常经营 Dashboard。

功能要求：

- 顶部展示欢迎语、业务状态、快捷入口和时间筛选。
- 指标卡片突出核心数字，辅助文字弱化，支持同比/环比趋势。
- 展示客户分析、签约分析、收款分析、人员排行等。
- 保持现代 SaaS 风格，不使用传统 ERP 厚重边框和大面积蓝色。

### 8.4 待办中心

目标：集中处理当前用户需要审批、确认、接收、阅读的事项。

待办类型：

- 全部待办。
- 消息提醒。
- 提及与回复。
- 设计师分配。
- 收款审批。
- 退款审批。
- 变更单审批。
- 报价接收。
- 合同审批。

功能要求：

- 左侧菜单展示待办数量红色圆形角标。
- 待办中心支持未处理/已处理/全部切换。
- 待办卡片展示客户、金额、当前节点、发送人、审批流等关键信息。
- 点击待办可跳转到客户详情、报价详情或工地详情对应 Tab。
- 审批类待办处理时必须选择签名，驳回需要填写意见。

### 8.5 客户管理列表

目标：快速查询、筛选、新增、导入和进入客户详情。

功能要求：

- 支持客户名称、手机号、小区、服务门店、邀约人等搜索。
- 支持状态、来源、门店、负责人等筛选。
- 更多筛选 UI 统一新 Design System。
- 支持分页，分页组件统一直角/圆角规则。
- 支持新增客户、批量导入、恢复删除客户等。
- 地图选点应支持搜索结果选择、当前用户定位符号、明确当前选择名称和地址。

客户字段：

- 客户姓名、手机号、微信号、来源、状态、当前动作、意向风格、预算、面积。
- 服务门店、邀约人、创建人、服务团队。
- 小区/楼盘、楼栋、单元、房号、是否无房号、详细地址、经纬度。
- 房屋类型、装修类型、是否交房、需求、备注。

校验要求：

- 客户姓名必填。
- 小区/楼盘必填。
- 装修面积必填且大于 0。
- 手机号和微信号至少填一项。
- 手机号如填写必须为 11 位数字。
- 地址定位坐标必须有效。

### 8.6 客户详情

目标：围绕一个客户完成从跟进到签约的连续操作。

Tab：

- 客户信息。
- 跟进记录。
- 量房资料。
- 设计方案。
- 定金/设计费。
- 预算报价。
- 合同资料。
- 操作记录。

客户信息要求：

- 展示客户基本信息、房屋信息、地址、状态、当前动作、服务团队。
- 服务团队展示角色、人员、来源和操作入口。
- 已签约客户部分资料限制编辑，避免破坏历史合同和工地数据。

跟进记录要求：

- 支持跟进场景快捷文案。
- 支持跟进方式、内容、下次跟进时间。
- 支持回复跟进、@ 提及服务团队成员。
- 支持跟进附件上传。
- 跟进动态按时间倒序展示。
- 删除跟进需二次确认，并保留必要操作记录。

量房资料/设计方案要求：

- 支持按类型归档文件、图片、在线链接。
- 扫码上传页面应简洁，量房码只上传量房资料，设计方案码只上传设计方案。
- 支持资料预览、重命名、删除、分享。

定金/设计费要求：

- 定金与设计费分 Tab 或清晰分组。
- 支持手动记录、扫码支付、主动收款。
- 主动收款必须明确选择款项类型，避免用户遗漏。
- 设计费支持固定金额、按报价比例、按直接费比例、按设计师等级面积计算。
- 退款流程状态清晰，驳回显示为“已关闭”。

预算报价要求：

- 展示报价版本、金额、状态、更新时间。
- 支持新建报价、复制副本、设为正式报价、撤销正式、发送设计师、编辑备注、删除。
- 删除报价移入回收站，可在报价合同模块恢复。

合同资料要求：

- 合同必须基于正式报价创建。
- 支持合同类型、合同模板、合同编号、合同名称、甲方信息、工程信息、合同金额、定金抵扣、收款计划、合同附件。
- 支持暂存草稿、创建合同、审批、签约、重签、删除草稿/未签合同、打印合同。
- 重签合同生成新合同，原合同保留为历史归档。

操作记录要求：

- 追踪客户资料、跟进、款项、报价、合同等变化。
- 显示操作人、时间、动作、内容。

### 8.7 报价合同

目标：管理客户报价记录，提供高效报价编辑工具。

列表要求：

- 按客户展示报价状态、报价金额、正式报价、报价数量、最近更新。
- 支持搜索、筛选、分页。
- 支持新建报价，选择客户和定额模板。
- 模板选择应显示推荐原因、模板模式、空间数量、项目数量、综合费用数量。

报价详情要求：

- 支持空间导航、分类分组、报价项目行编辑。
- 支持键盘方向键像 Excel 一样移动输入框。
- 支持新增行、复制行、删除行、拖拽排序。
- 支持综合费用、直接费、税费、折扣、最终金额计算。
- 滑动时固定区域不能露出内容空隙，需通过背景层或 sticky 容器遮挡。
- 支持导出表格和打印。

### 8.8 工地管理

目标：集中管理签约后的施工工地。

列表要求：

- 状态筛选：全部、待开工、开工确认、施工中、业主结算、工地结算。
- 展示客户、项目地址、项目经理、施工阶段、计划/实际时间、收款、签到、摄像头等摘要。
- 支持分页和大屏自适应。

详情 Tab：

- 工地信息：合同、地址、面积、项目经理、阶段、开工信息。
- 客户收款：展示本工地款项和流水。
- 施工计划：按施工模板和面积生成计划节点。
- 施工阶段：推进施工/验收节点，查看标准和上传照片。
- 施工记录：集中展示所有节点相关操作，包括状态变更、施工汇报、问题整改、附件上传。
- 材料下单：从工地发起辅材订单。
- 增减项单：记录增项/减项，支持审批和业主确认。
- 成本支出：记录人工、材料、其他成本。
- 工地摄像头：接入萤石摄像头，播放实时画面。
- 工地签到：生成签到码，查看签到记录和照片。
- 资料归档：施工图、效果图、水电 VR、主材选材单、结算单、报价单、合同资料、优惠单、其他资料。

开工交底要求：

- 完成交底时必须选择施工模板。
- 施工模板必须包含施工阶段。
- 必须填写计划开工和签约工期。
- 开工交底完成后只能查看，不允许随意修改资料。
- 确认开工时必须校验交底和施工模板，避免死路。

施工记录要求：

- 用户可点击施工节点状态，下方内容栏展示谁在什么时候完成该任务。
- 记录来源包括节点状态、日报、附件、问题整改、验收确认。
- 记录按时间倒序展示，可按节点筛选。

工地摄像头要求：

- 支持添加摄像头：名称、安装位置、设备序列号、通道号、设备验证码、业主可见。
- 验证码加密保存，列表只显示是否已保存或脱敏值。
- 支持编辑、删除；删除不影响萤石平台设备。
- 点击摄像头 Tab 后自动获取并播放实时画面。
- 接入依赖萤石开放平台 AppKey/AccessToken 等服务端配置。
- 摄像头异常时提示清晰原因，如 Token 失效、设备离线、验证码错误、接口异常。

### 8.9 财务中心

目标：统一管理业主收款、退款、人工结算。

业主收款要求：

- 按工地聚合展示定金、设计费、工程款、变更款。
- 最近款项记录显示在最上方。
- 订单详情中只展示同类型的本工地其他单据，例如定金详情只显示其他定金单据，不显示设计费、工程款、变更款。
- 本工地其他单据与具体款项使用一致横条样式。
- 支持收款审批、退款审批、退款打款处理。
- 驳回类退款状态统一展示为“已关闭”。

人工结算要求：

- 清除假数据。
- 支持工人结算、项目经理结算、人工报销、劳务结算分类。
- 支持待审核、待付款、付款中、已结清、需调整状态。
- 支持结算明细和操作记录展示。

### 8.10 定额管理

目标：维护报价使用的标准定额和报价模板。

定额库要求：

- 维护项目名称、类别、空间、单位、人工单价、材料单价、规格、备注等。
- 支持搜索、分类、启用/停用。
- UI 遵守新 Design System。

定额模板要求：

- 支持多套模板。
- 支持空间、空间内项目、综合费用。
- 支持套餐报价模式、面积区间、超出面积价格。
- 支持模板启用/停用、复制、编辑、删除草稿。
- 模板被报价使用后需保留历史稳定性。

### 8.11 材料管理

目标：维护材料主数据、库存和入库。

材料库要求：

- 字段包括材料编码、品名、品牌、产品名、型号、颜色、规格、单位、采购价、售价、材料类型、供应商、图片、状态。
- 材料编码必须以 `XY` 开头。
- 支持新增、编辑、导入、上架、下架、批量操作。
- 供应商必须为合作中状态，才能新增/导入可用材料。

库存管理要求：

- 展示库存数量、最低库存、库存预警。
- 支持库存变动记录。
- 结合订单出库和入库单变动。

入库单要求：

- 支持创建入库单、选择供应商、添加材料明细。
- 入库后增加库存并记录库存流水。

### 8.12 订单管理

目标：管理工地辅材订单。

辅材订单要求：

- 支持仓库订单和月结供应商订单。
- 新建订单需选择工地、仓库/供应商、材料和数量。
- 仓库订单需通过“确认出库”处理，不能直接改为已出库。
- 出库数量必须大于 0 且不能超过合理范围。
- 支持订单状态流转、取消、导出。
- 订单详情展示材料明细、数量、单价、金额、出库情况。

### 8.13 供应商管理

目标：维护供应商档案和结算信息。

功能要求：

- 供应商基础信息：名称、类型、联系人、电话、地址、合作状态、备注。
- 支持供应商账户信息。
- 支持材料关联数量展示。
- 停止合作的供应商不能用于新增材料或订单。

### 8.14 组织权限

目标：维护组织架构、员工和角色权限。

组织管理要求：

- 支持集团、大区、分公司、门店、部门、小组等层级。
- 支持组织负责人。
- 支持启用/停用。
- 停用组织会影响员工归属、客户服务门店、下单与分公司设置。

团队管理要求：

- 维护员工姓名、手机号、邮箱、角色、组织、工号、入职日期、备注、头像、启用状态。
- 支持员工导入。
- 支持员工离职/停用。

角色管理要求：

- 支持角色名称、角色编码、描述、权限点、数据范围、启用状态。
- 数据范围包括仅自己、本小组、本部门、本门店、本分公司、本大区、全集团。

目标：按分公司配置业务规则。

基本信息：

- 法人、负责人、联系电话、营业执照号、省市区、地址。

收款比例：

- 支持多套收款方案。
- 支持默认方案。
- 支持收款阶段和比例。
- 支持收款二维码、收款账户名称、收款说明。

合同模板：

- 见 7.5。

收费比例：

功能开关：

## 10. 第三方与外部能力

### 10.1 萤石摄像头

- 服务端通过萤石开放平台配置获取播放能力。
- 系统保存工地摄像头设备序列号、通道号、验证码。
- 验证码加密存储，前端仅展示脱敏或是否已保存。
- 播放失败需要提示用户检查设备在线、验证码、Token、平台配置。

### 10.2 地图定位

- 客户地址和工地签到依赖地图搜索、逆地址解析和定位能力。
- 地图选点需要明确区分“搜索结果”“当前用户位置”“当前选择点”。
- 右下角当前选择必须与用户最终点击点一致，避免点击 POI 后仍显示附近小区。

### 10.3 Word 导入

- 合同模板支持 `.docx` 导入。
- 限制文件大小 15MB。
- 旧版 `.doc` 需用户另存为 `.docx`。
- 导入后需清理不安全 HTML，保留可编辑正文和表格。

## 11. 安全与合规要求

- `.env`、数据库、上传文件不得被代码发布覆盖。
- `JWT_SECRET` 必须在正式环境配置且长度不低于 32 字符。
- 摄像头验证码、第三方 Token、密钥不得写入前端。
- 上传文件限制类型和大小。
- 在线链接只允许 `http` 或 `https`。
- 文件访问需验证登录和数据权限；公开分享链接需 Token 与过期时间。
- 财务、合同、客户敏感操作需操作日志。
- 审批签字需保存签名快照，防止用户后续修改个人签名影响历史审批。

## 12. 性能要求

- 本地开发默认端口 3459，需避免重复服务占用导致卡顿。
- 页面切换时左侧菜单立即响应。
- 列表使用分页，避免一次性渲染过多数据。
- 大表格只渲染必要列，必要时横向滚动。
- 搜索防抖，避免每输入一个字都请求接口。
- 图片懒加载。
- 待办数量轮询需节制，避免频繁请求导致卡顿。
- 开发构建和正式构建需区分 `.next-dev` 与 `.next-build`。

## 13. 发布与环境要求

正式环境更新原则：

- 只同步代码功能，不同步用户数据。
- 不覆盖 `.env`。
- 不覆盖 `prisma/*.db`。
- 不覆盖 `public/uploads`。
- 每次发布前备份正式代码和数据库。
- 先在临时目录解压、安装依赖、构建成功，再同步到生产目录。
- 使用 PM2 管理服务，发布后重启 `renovation-saas`。
- Nginx 需透传 `Host`、`X-Forwarded-Host`、`X-Forwarded-Proto`、`X-Forwarded-For`，保证登录来源校验正常。

## 14. 验收清单

### 14.1 登录与权限

- 正确账号可登录。
- 错误密码提示明确。
- 会话过期后自动跳转登录页。
- 无权限用户访问接口返回 403。
- 不同角色只能看到授权范围数据。

### 14.2 客户链路

- 新增客户字段校验正确。
- 地图选点当前选择准确。
- 跟进、回复、附件、@ 提及正常。
- 量房资料和设计方案扫码上传分类正确。
- 定金/设计费主动收款必须选择款项类型。
- 报价、合同能从客户详情连续完成。

### 14.3 报价合同

- 新建报价能正确带入模板。
- 综合费用金额正确。
- 键盘方向键可移动输入框。
- 报价保存、导出、设为正式、复制、删除正常。
- 合同模板可保存、发布、停用、删除草稿。
- 同类型合同只允许一个已发布模板。
- Word 导入后可编辑且不吞内容。
- 合同打印使用当前冻结模板版本。

### 14.4 工地施工

- 未选择施工模板不能完成开工交底。
- 未完成开工交底不能确认开工。
- 确认开工后生成施工计划和阶段。
- 节点状态点击后能展示完成人和完成时间。
- 施工记录能聚合节点操作、附件、日志和问题。
- 工地签到码、签到记录、照片正常。
- 摄像头可新增、编辑、删除、播放，异常提示明确。

### 14.5 财务

- 业主收款最近记录在最上方。
- 定金详情只显示同工地其他定金单据，不混入设计费、工程款、变更款。
- 退款驳回显示“已关闭”。
- 审批必须选择签名。
- 人工结算无假数据。

### 14.6 UI

- 新 Design System 在列表、详情、弹窗、下拉、分页中统一。
- 已升级页面不被重复改坏。
- 页面大屏自适应。
- 不出现大面积蓝色、厚重边框、混乱圆角和按钮变形。

## 15. 后续建议

- 建立统一组件库文档，把按钮、输入框、下拉、表格、Tab、弹窗、状态标签固化为可复用组件。
- 建立数据库迁移机制，减少动态建表和运行时 `ALTER TABLE` 带来的不确定性。
- 增加自动化测试覆盖登录、权限、收款、退款、合同模板、开工交底、报价计算。
- 优化本地开发性能，检查待办轮询、路由预取、大页面渲染和图片加载。
- 为正式环境发布建立一键脚本和回滚脚本，降低手动上传风险。
- 为萤石摄像头增加 Token 自动刷新和设备状态诊断页。
- 为合同模板增加更稳定的分页预览和打印预览一致性校验。
